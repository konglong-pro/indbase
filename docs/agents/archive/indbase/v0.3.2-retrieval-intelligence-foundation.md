## Mission

Build the deterministic retrieval package layer that future `indb ask` will consume.

Short version:

```text
Search returns snippets.
Retrieve returns auditable evidence packages.
Ask remains out of scope.
```

v0.3.2 is not an answer-generation phase. It produces local, deterministic, citation-ready packages bound to source chunks.

## Non-negotiables

- Do not implement `indb ask`.
- Do not generate answers, summaries, claims, cards, or notes.
- Do not write `citations`.
- Do not write source Markdown, document revisions, chunks, source files, originals, or output artifacts.
- Do not mutate tags, aliases, categories, document tag assignments, profiles, or feature atoms.
- Do not automatically build profiles or run taxonomy analysis.
- Do not use pending suggestions or tag candidates in retrieval ranking.
- Do not call real LLM providers, read API keys, send network model calls, or add provider dependencies.
- Do not change default `indb search` ranking or behavior.
- Do not let retrieval fix taxonomy.

## Architecture Boundary

indbase retrieval owns:

- deterministic query parsing
- explicit filter resolution
- wrapping existing search candidate generation
- accepted taxonomy/profile signal loading
- deterministic boost scoring
- quote extraction
- diversity limiting
- retrieval run and item persistence
- retrieval CLI rendering
- doctor integrity checks

indbase retrieval may read:

- current documents and chunks
- accepted categories
- active tags and aliases
- active document tag assignments
- active profiles
- active feature atoms
- existing search results

indbase retrieval must not own:

- taxonomy mutation
- profile generation
- feature extraction
- output generation
- citation creation
- answer generation
- provider calls

## Confirmed Execution Rules

These decisions are part of the v0.3.2 implementation contract.

### Public Commands

Add:

```text
indb retrieve <query>
indb retrieval list
indb retrieval show <retrieval_run_id>
```

Do not replace `indb search`. Do not make users run `indb retrieve run <query>`.

### Persistence

`indb retrieve` persists by default.

Persist only retrieval audit records:

- `retrieval_runs`
- `retrieval_items`

Do not persist:

- `citations`
- `output_runs`
- output files
- source revisions
- chunks
- taxonomy mutations
- profiles

### Planner

Use deterministic planner logic only.

Allowed:

- rule-based query parsing
- exact taxonomy name or alias matching
- feature atom text matching
- bounded deterministic boosts

Forbidden:

- real provider calls
- fake-provider dependency for main retrieval behavior
- hidden network access
- nondeterministic reranking

### Filters

Support explicit filters:

```text
tag:<tag-id-or-name-or-alias>
category:<category-id-or-name>
```

Rules:

- explicit filters are hard filters
- natural language taxonomy matches are soft boosts
- ambiguous filters fail
- missing filters fail
- inactive taxonomy objects do not resolve
- multiple explicit filters use deterministic AND semantics unless the canonical spec is updated

### Signals

Use:

- active categories
- active managed tags
- active accepted document tag assignments
- active document profiles
- active feature atoms from current revisions

Ignore:

- pending taxonomy suggestions
- pending tag candidates
- stale profiles
- stale feature atoms
- archived documents
- source shells
- old non-current revisions during new retrieval runs

Historical persisted retrieval items may still point to old revisions after later re-ingest. That is valid if the referenced rows still exist and the quote still matches the chunk.

### Candidate Generation

Default mode:

```text
hybrid
```

Use existing search service behavior for candidate generation. Do not rewrite search ranking as part of v0.3.2.

Expose:

```text
--mode fts|vector|hybrid
--top-k <n>
--candidate-k <n>
--per-doc-limit <n>
```

Default:

```text
per_doc_limit = 3
candidate_k = max(top_k * 5, 25)
```

### Evidence

Each item must bind to:

- `doc_id`
- `revision_id`
- `chunk_id`
- exact source quote

The quote must be an exact substring of `chunks.text`.

Snippet text is display-only and does not satisfy citation readiness by itself.

Every boost or filter effect must appear in `reasons_json`.

### Missing Profiles

Do not auto-build profiles.

If a retrieved candidate lacks an active profile, keep base search eligibility and add a warning/reason. Tell the user to run explicit profile/taxonomy commands if profile-based boosts are desired.

## Schema Rules

Add:

- `retrieval_runs`
- `retrieval_items`

Use ID prefixes:

```text
retrrun
retritem
```

Required run fields:

- query text
- normalized query
- planner version
- base mode
- linked search query id when available
- filters JSON
- planner JSON
- warnings JSON
- top_k
- candidate_k
- per_doc_limit
- result count
- status
- timestamps

Required item fields:

- run id
- rank
- doc id
- revision id
- chunk id
- title
- source path
- quote
- snippet
- base score
- taxonomy score
- final score
- match source
- reasons JSON
- timestamp

## Doctor Expectations

Default doctor must check retrieval integrity without rerunning retrieval and without calling LLMs.

Add findings for:

- invalid JSON on retrieval runs or items
- run result count mismatch
- item referencing missing run, doc, revision, or chunk
- item chunk/revision mismatch
- empty quote
- quote not found in chunk text
- invalid rank sequence or duplicate rank per run

Doctor diagnoses only. It must not repair retrieval records.

## Test Expectations

Add focused tests for:

- migration applies cleanly
- `retrieve` persists run and items
- `retrieval list/show` reads persisted packages
- explicit tag filter resolves by id, name, and alias
- explicit category filter resolves by id and name
- ambiguous filters fail
- missing filters fail
- pending taxonomy artifacts do not affect ranking
- archived docs and source shells are excluded
- missing profiles do not trigger profile writes
- item quotes are exact chunk substrings
- no `citations`, source revisions, chunks, output artifacts, or taxonomy mutations are written
- default per-document limit is enforced
- doctor catches broken retrieval records

Add a deterministic gate script:

```text
scripts/v032_retrieval_release_gate.py
```
