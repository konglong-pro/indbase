# Transition Output Integration Agent Guide

Read this before implementing the v0.2 transition-backed output integration.

Canonical project spec:

- `docs/planning/archive/v0.2/transition-output-integration.plan.md`

Baseline context:

- `AGENTS.md`

- `docs/planning/archive/v0.2/swallow-ingest-integration.plan.md`
- `docs/planning/archive/v0.1/mvp-v0.1-spec.plan.md`

## Mission

Integrate transition as indbase's output-layer renderer while preserving indbase's trust boundary.

Short version:

```text
transition owns standardization and export rendering
indbase owns trust
export artifact != source revision
source replacement creates a new immutable revision
default search = source revisions only
```

## Non-negotiables

- Do not overwrite canonical Markdown in place.
- Do not let transition change indbase IDs, frontmatter, citations, quotes, code, math, or protected blocks.
- Do not let transition create or update `doc_id`, `revision_id`, `chunk_id`, tasks, errors, or doctor state directly.
- Do not use a transition HTTP service.
- Do not parse transition CLI text as a stable API.
- Do not auto-discover project `transition.config.*` files.
- Do not index export artifacts in default search.
- Do not delete old revisions or old chunks.
- Do not make transition output bypass task, error, artifact, or doctor visibility.

## Architecture Boundary

indbase keeps ownership of:

- document identity
- source revision creation
- output run records
- output artifact records
- source binding records
- frontmatter
- protected content validation
- vault paths
- tasks and errors
- immutable revision rules
- chunking
- FTS/vector indexing
- doctor checks

transition owns:

- Markdown standardization
- HTML rendering
- PDF rendering
- DOCX rendering
- format diagnostics
- render traces and manifests

Operational summary for implementers:

| Topic | Rule |
| --- | --- |
| Protected content | A+B: `protected_spans` in bridge request + byte-for-byte validation after response |
| Locator mapping v1 | P1: same `heading_path` and identical chunk `text` → `exact`; else `parent_only` |
| Locator mapping v1.1 | P2: protected-span coverage (follow-up) |
| Node | Host responsibility; indbase detects only |
| transition runtime | Per-vault `.indbase/runtime/transition/`; explicit `output runtime install` only |
| Feature flag | F1: default false; true only after install; hand-edit without runtime must fail |
| Bridge contract | C1: indbase-owned `contract_version: 1` |
| Bridge call | B1+B3: one subprocess per run; file transport for large JSON |
| Export v1 inputs | E3: source revision, translation output, accepted atomic note |
| Export `--to` | T1+T3: always write `normalized.md`; `--to` is html/pdf/docx only; default md-only |
| Normalize failure | Nf2: keep failed `output_run` evidence; never change current on failure |
| Failed promotion | Rvs1: `promotion_status = never_promoted` if chunk/FTS fails |
| Archive export | L1: allow with `input_archived` / `input_stale` warnings; normalize rejects archived/shell |

| Atomic note export | N-cli1 + N-bind1 + N-prot2 |

| Concurrency | Lck2: parallel export; one normalize per doc |
| Runtime reinstall | Up1: historical runs keep recorded commit/hash |
| Bridge timeout | Tm1 default 300s; Art1 failed runs publish no export artifacts |

## Protected Span Detection (v1)

Implement in indbase, not in `transition.config.json`.

**Normalize (N-A1)**: send body bytes and body `protected_spans` only; indbase writes new `indbase.source.v1` frontmatter after success.

**All export reads (E-C1)**: one protected span for the full YAML frontmatter fence, then S-std on the body.

**S-std body detectors**:

- B1 fenced code blocks
- B2 block quotes
- B3 display math (`$$ … $$`)
- Skip inline backtick code in v1 (v1.1 optional)

**Citations (D)**: no separate cite parser in v1; quotes are protected via B2 or future indbase literal sentinels.

**Translation files (T-prot2)**: also protect each `### Source` section up to (but not including) `### Translation`.

**Accepted atomic notes (N-prot2)**: also protect each `Citations:` block through the end of that claim section; claim prose above `Citations:` may be standardized.

Always validate protected spans with A+B after the bridge returns.

## Runtime Install

- Commands: `indb output runtime install`, `indb output runtime status`.
- Runtime root: `vault/.indbase/runtime/transition/`.
- `runtime install` is the **only** indbase entry point allowed to run `npm install`.
- Do **not** install on `init`, `doctor`, first export, or first normalize.
- On successful install, set `features.transition_output = true` in vault config.
- Pin transition with the git SHA from the planning doc; copy the bridge template from the indbase package into the runtime directory.
- Reinstall is allowed (Up1). Do not rewrite metadata on existing `output_runs`. Warn when older runs used a previous pin.

## Feature Flag (F1)

- Default `transition_output = false` in `default_config` and new vaults.
- Reject output commands when false (`transition_output_disabled`).
- Reject output commands when true but runtime is incomplete (`transition_runtime_missing`).
- Ingest, search, `doc show`, archive/restore, and review flows must not depend on this flag.

## Bridge Contract (C1)

- Freeze request/response schema in the indbase repository (JSON Schema or typed models + generated schema).
- Include at minimum: `contract_version`, `mode`, `input_kind`, `markdown`, `protected_spans`, `targets`, paths, `config_hash` on request; `normalized_markdown`, per-target results, evidence paths, and errors on response.
- Store `contract_version`, `transition_commit`, and `config_hash` on each `output_run`.
- Ship golden fixtures under `tests/fixtures/transition_bridge/` for fake bridge tests.
- Vault `transition-bridge.mjs` adapts the pinned SDK to indbase field names; do not treat transition CLI stdout as API output.
- Subprocess timeout defaults to 300 seconds (`bridge_timeout_seconds`, Cfg1). Timeout or bridge crash → failed run; do not write export artifacts under `outputs/exports/` (Art1).
- When a run fails but the bridge left durable evidence (manifest/trace/report in the job dir or response), copy it into `.indbase/artifacts/output_runs/<output_run_id>/` and set `output_runs.evidence_*` columns. Write `input_hashes.json` with `"partial": true` when normalized Markdown was not produced. Do not treat partial evidence as a successful export.

## Transition Config (Cfg1)

- Whitelist keys only; reject forbidden keys at `runtime install` and before each bridge call.
- Forbidden: source-binding rewrite, external config discovery, in-place source writeback, paths outside the vault.
- Allowed: render defaults, fonts/CJK, trace level, vault-local cache paths.
- Hand-edited configs that fail validation block output commands (`transition_config_invalid`) without silently reverting the file.

## Read-only Export Rules

`output export` must not change the source object.

Rules:

- v1 must support all three inputs: source revision (optional `--revision`), translation output, accepted atomic note.
- It may read archived documents and non-current revisions; set `input_archived` / `input_stale` and print a warning (L1).
- It must create an `output_run`.
- It must always write and validate `outputs/exports/<output_run_id>/normalized.md`.
- `--to` accepts only `html`, `pdf`, and `docx`. No `--to md`. No `--to` means md-only.
- It must copy required evidence into `.indbase/artifacts/output_runs/<output_run_id>/`.
- It must record hashes for every successful artifact.
- It must mark the run `partial` when `normalized.md` succeeds but a **requested** html/pdf/docx target fails.
- It must mark the run `failed` when `normalized.md` or protected validation fails.
- It must not create chunks or default search rows.

### Translation export

- Command: `indb output export translation <translation_id>` (T-cli1).
- Require `translations.status = succeeded` and `outputs/translations/...` file presence.
- `output_sources`: one row per DB `source_chunk_id` with `mapping_confidence = exact` (T-bind1).
- Apply T-prot2 protected spans in addition to E-C1 and S-std.

### Accepted atomic note export

- Command: `indb output export note <candidate_card_id>` (N-cli1).
- Require accepted card, `notes/atomic/` path, and frontmatter `candidate_card_id` match.
- `output_sources`: one row per `candidate_card_sources.source_chunk_id` (N-bind1).
- Apply N-prot2 protected spans in addition to E-C1 and S-std.

## Normalize Replacement Rules

`doc normalize --replace-current` changes a document by creating a new source revision.

Rules:

- Reject source shells.
- Reject archived documents.
- Reject missing or unreadable current revisions.
- Run transition against the current source revision; indbase supplies `protected_spans` and validates protected bytes afterward (A+B).
- Validate protected content **before** writing a new `sources/...` file.
- Write a new `sources/...__rev_000N.md` file with indbase-written frontmatter and transition-normalized body.
- Insert a new `document_revisions` row with derivation fields and `promotion_status`.
- Link the new revision to the parent revision and output run.
- Mark old current chunks as non-current without deleting them.
- Chunk and index the new revision.
- Update `documents.current_revision_id` and `canonical_path` only after chunking and default FTS succeed (Idx1); then set new revision `promotion_status = promoted` and mark the prior current revision `superseded`.
- If chunking or FTS fails after the revision row exists, set `promotion_status = never_promoted` and leave the previous revision current.
- When `features.embedding = true`, mark embeddings stale after promotion and instruct the operator to rebuild vectors; do not fail promotion if vector rebuild is unavailable in v1.
- Failed normalize may still persist `output_run` rows and evidence (Nf2).
- Reject a second in-flight normalize for the same `doc_id` (`normalize_already_running`, Lck2).

Never point `documents.canonical_path` at `outputs/exports`.

## Protected Content Rules

Protect and validate:

- indbase frontmatter
- `doc_id`
- `revision_id`
- source doc, revision, and chunk IDs
- citations
- source excerpts
- quote blocks
- code blocks
- math blocks
- other indbase-marked literal blocks

Bridge contract (A+B):

- indbase computes `protected_spans` and sends them in the C1 request.
- indbase verifies every protected span is byte-identical in bridge output.
- If protected body content changes, fail the run before creating a replacement revision.

For replacement revisions, indbase writes new frontmatter after transition returns the normalized body. Transition must not own frontmatter fields.

## Artifact Rules

transition cache is not durable evidence.

Required durable evidence should be copied into:

```text
.indbase/artifacts/output_runs/<output_run_id>/
```

User-visible export files should be written into:

```text
outputs/exports/<output_run_id>/
```

Do not store durable DB paths that point to:

- temp directories
- absolute paths
- parent-directory escapes
- transition cache
- another vault

## Locator Carry-forward

v1 (P1):

- After normalize, rechunk with `markdown_heading_v1`.
- Copy `source_locator_json` only when old and new chunks share `heading_path` and identical `text` bytes (`mapping_confidence = exact`).
- Otherwise write `output_sources` with `mapping_confidence = parent_only` and no copied locators.

v1.1 (P2): allow inheritance when old chunk text is fully covered by protected spans that pass A+B validation.

## Doctor Expectations

Default doctor should validate existing output state:

- output run references
- output artifact paths
- artifact hashes
- evidence manifests and traces
- source bindings
- created revision links
- export artifacts excluded from default search
- promoted replacement revisions have chunks and index rows
- `never_promoted` revisions are not current and are not default-searchable
- old revisions still exist
- `transition_output = true` without runtime may be reported
- failed normalize runs do not imply an incorrect current revision

Deep doctor may check heavy runtime dependencies:

- Node on PATH
- transition package import in the vault runtime
- bridge JSON contract smoke (one subprocess; not install)
- pandoc
- PDF engine
- CJK fonts
- DOCX export

Doctor diagnoses only. It must not regenerate transition outputs, mutate output records, run `npm install`, or change `transition_output`.

## Test Expectations

Run focused tests first, then doctor/search/revision tests.

Required assertions:

- canonical Markdown is never overwritten in place
- `output export` creates derived artifacts only
- `doc normalize --replace-current` creates a new revision
- old revisions remain queryable
- new replacement revision becomes current and searchable
- export artifacts do not appear in default search
- protected content changes fail
- partial target failures are visible
- artifact hashes are checked
- missing evidence is reported by doctor
- source locator carry-forward only happens when mapping is provable (v1: P1 exact text match)
- archived and stale revision exports are allowed with warnings
- normalize leaves `never_promoted` on chunk/FTS failure
- explicit runtime install is required before `transition_output` is honored
- translation and atomic note exports use DB ids and exact source bindings
- Cfg1 rejects forbidden transition config keys
- bridge timeout fails the run without publishing export artifacts
- concurrent normalize on the same document is rejected

Prefer fake bridge fixtures for deterministic unit tests. Use real transition only in smoke tests guarded by runtime availability checks.

### Real Node bridge smoke (opt-in)

- Unit tests: `tests/test_transition_partial_evidence.py` (fake failed bridge with evidence).
- Smoke: `tests/test_transition_bridge_smoke.py`, marker `transition_smoke`.
- Enable with `INDBASE_TRANSITION_SMOKE=1`, Node on PATH, and `indb output runtime install` in the vault under test.
- Optional: `INDBASE_TRANSITION_SMOKE_INSTALL=1` to run `npm install` during the smoke fixture (CI or first local run).
- Default pytest runs skip smoke unless the env var is set.
