## Objective

Coordinate consoler-owned indbase NL v2 assisted intent drafting without expanding indbase.

Success means:

```text
consoler can use explicit opt-in assisted drafting for indbase variant
provider context is tightly audited
one reviewable Source Trust Loop form opens
normal consoler lifecycle remains required
indbase command and artifact contracts stay stable
no indbase core feature is added
```

## Scope

Indbase-side scope:

- planning docs
- agent routing docs
- `CONTEXT.md` glossary
- optional coordination contract test
- optional project-status/testing closeout docs after implementation evidence exists
- smallest `indbase_agent` contract fix only if consoler V4g proves a real adapter defect

Consoler-side implementation is owned by:

## Do Not Touch

- Do not add indbase commands.
- Do not add natural-language parsing to `indbase_agent`.
- Do not send raw natural language to `indbase_agent`.
- Do not change `indbase_core`.
- Do not add migrations.
- Do not add durable UX state or vault preference storage.
- Do not add provider setup, provider credentials, provider endpoint, provider model, prompt, or response storage in indbase.
- Do not add title/path lookup, vault discovery, vault list, vault browser, source browser, full source viewer, Web UI, or artifact gallery.
- Do not add review/category/tag mutation, doctor repair, retrieval packages, `ask`, embeddings, generated answers, chat, follow-up suggestions, or multi-action workflows.
- Do not change consoler protocol/runtime/store/schema from this repository.
- Do not commit private vault paths, source snippets, provider prompts, provider responses, raw traces, temp vaults, runtime SQLite files, logs, screenshots with private content, or local path secrets.

## Done Means

- The consoler V4g gate passes.
- Provider context audit proves forbidden context is not sent to the provider.
- Provider suggestions are validated against the scoped Source Trust commands and schema.
- Deterministic complete candidates do not call provider.
- Assisted success and fallback notices are transient and non-sensitive.
- NL submit opens editable forms only and does not enter the action lifecycle until user submission.
- Session `vault_path` remains TUI form-layer convenience only.
- Indbase adapter changes, if any, are narrow and test-backed.
- No indbase core feature, new command, migration, raw NL parser, durable UX state, vault browser, Web UI, mutation workflow, retrieval package, `ask`, embedding, generated answer, default assisted behavior, or consoler protocol/runtime/store/schema change was added.
