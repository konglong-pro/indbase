# Archived Indbase Agent Rules

Historical v0.3.4 rules. Do not read by default unless doing provider-evidence
phase archaeology or regression repair.

## Current Phase

- Phase: `v0.3.4`
- Title: Provider Evidence / Trust Correlation
- Canonical spec:
  `docs/planning/archive/v0.3.4/provider-evidence-trust-correlation.plan.md`
- Gate: `uv run python scripts/provider_fake_release_gate.py`

## Mission

Make indbase consume packaged providers without making swallow or transition
special trusted stages.

Short form:

```text
Providers produce evidence.
indbase copies evidence.
indbase decides trust.
indbase owns state.
```

## Allowed Work

- Provider capability contracts under `src/indbase_core/capabilities/`.
- Evidence package types and evidence copy store under `src/indbase_core/artifacts/`.
- Provider ports for ingest and Markdown output.
- Fake ingest/output providers for deterministic tests.
- Swallow adapter extraction under `src/indbase_integrations/swallow/`.
- Transition adapter extraction under `src/indbase_integrations/transition/`.
- Provider binding config, vault-local administrative override, and provider run
  metadata.
- `provider_runs` table, per-attempt evidence roots, and adopted provider run
  links on ingest/converter/output records.
- Provider error taxonomy mapping into tasks, errors, review items, and output
  warnings.
- Provider-aware doctor sections.
- Provider evidence summary views using `indbase://...` URIs.
- Consoler operation trace metadata emitted by `indbase_agent` without provider
  backend coupling.
- Search pollution tests for candidates, evidence, exports, and normalize flows.

## Do Not Add

- `ask`, generated answers, LLM judges, summaries, claims, cards, or notes.
- Default HTTP, queue, or MCP provider profiles.
- Provider backend selection as an ordinary user-facing command option.
- Direct swallow or transition calls from `indbase_agent`.
- Provider URIs or cache paths in consoler artifact blocks.
- Direct provider-result-to-revision writes.
- Default source search over unpromoted candidates, copied evidence files, old
  revisions, or export artifacts.
- Broad rewrites of retrieval, taxonomy, source search ranking, or answer
  readiness.
- A vault browser, provider job browser, or artifact gallery.

## Required Boundaries

- `indbase_core` defines ports and contracts.
- `indbase_integrations` implements provider adapters.
- Repository/package bindings are the default; explicit vault-local admin config
  may override them only within the provider contract.
- Ordinary user commands must not expose provider backend selection.
- Provider cache is disposable.
- `.indbase/artifacts/provider_runs/<provider_run_id>/` copied evidence is
  durable.
- `provider_runs` is per provider attempt; default v0.3.4 behavior is one
  attempt per operation with no automatic retry/fallback.
- `provider_status` and `evidence_status` are separate.
- Ingest/output records use `adopted_provider_run_id`, not a generic
  `provider_run_id`.
- Promotion policy decides whether ingest evidence becomes a source revision.
- Output service records derived artifacts without mutating source revisions,
  except normalize `--replace-current`, which creates a new immutable revision.
- Normalize without `--replace-current` records a derived candidate/output
  artifact only.
- Provider-backed agent commands include capability refs in operation trace;
  read-only commands still emit operation trace without capability refs.
- Provider ids are logical ids; capability ids are globally namespaced; dynamic
  provider loading is out of scope for v0.3.4.

Real provider smoke remains opt-in and environment-gated.

Provider smoke policy:

```powershell
$env:INDBASE_PROVIDER_SMOKE='1'
$env:INDBASE_PROVIDER_SMOKE_REQUIRED='1'
```

Missing real provider runtime is an explicit skip by default and a failure only
when `INDBASE_PROVIDER_SMOKE_REQUIRED=1`.
