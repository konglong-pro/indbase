## Objective

Make v0.3.2 tag governance behavior regression-testable through a deterministic tag harness.

Success means:

```text
Explicit fixtures prove governed tag behavior.
Wrong trusted tag metadata is caught.
Manual tags are protected.
Trusted tag filters stay unpolluted.
Tag quantity control is explainable.
The v0.3.2.1 release gate is stable enough for CI.
```

## Scope

Implement only Tag Harness Hardening:

- explicit fixture schema
- sanitized fixture suite
- isolated eval vault runner
- case/candidate/document/run-level evaluation
- summary JSON
- failure JSONL / diagnostic artifact
- stable reason codes
- exact expectation matching
- trusted tag search checks
- feedback-derived sanitized regression cases
- release gate script
- CI job after local pass
- docs/testing and project-status updates after implementation

Do not implement:

- formal `indb tag harness` CLI
- production schema/migration by default
- provider-backed tagger
- embeddings
- network calls
- search ranking or hybrid changes
- query expansion
- retrieval packages
- `ask`
- automatic policy mutation
- production vault harness run history
- raw private fixture commits
- swallow/transition/OCR/PDF validation
- replacement tag governance engine

## Non-Negotiables

- Harness must be deterministic and local.
- Harness must not read API keys or call network services.
- Harness must use an isolated eval vault by default.
- Harness must not mutate a user's production vault.
- Harness must not mutate tag policy, aliases, merges, scopes, blocklists, budgets, or applied tags without explicit review/accept workflows.
- Harness must call existing tag governance/tagger/search services.
- Exact case expectation matching is required for hard-gate fixtures.
- Summary JSON is the CI contract.
- Failure records need stable reason codes.
- Repo fixtures must be synthetic or sanitized.
- Candidate precision/recall are report-only in v0.3.2.1.
- Do not update README unless a formal user-facing command is added.

## Execution Slices

### Slice 1: fixture schema and failing tests

Add `tests/test_v0321_tag_harness.py` and `tests/fixtures/v0321_tag_harness/`.

Cover:

- schema validation
- unsupported keys rejected
- sanitized source markers
- hard-gate expectation shape
- summary shape
- failure record shape

Command:

```powershell
uv run python -m pytest tests/test_v0321_tag_harness.py -q
```

### Slice 2: evaluation runner

Add a pure harness evaluation module.

Responsibilities:

- load fixtures
- create eval vault
- seed trusted documents/chunks/FTS
- seed tags, aliases, lifecycle, scope, blocklist, manual tags
- run existing deterministic tagger
- compare expectations
- collect metrics and failures

Command:

```powershell
uv run python -m pytest tests/test_v0321_tag_harness.py tests/test_v032_tag_governance.py -q
```

### Slice 3: search and feedback checks

Add cases for:

- trusted tag filter exact hits
- alias-to-canonical search
- candidate/rejected/blocked tags not filterable
- feedback-derived sanitized regression cases

Do not change ranking, hybrid search, retrieval packages, or `ask`.

### Slice 4: release gate

Add:

```text
scripts/v0321_tag_harness_release_gate.py
```

Gate behavior:

- print stable summary JSON
- exit `0` only when all hard gates pass
- include failure records/artifacts for debugging

Command:

```powershell
uv run python scripts/v0321_tag_harness_release_gate.py
```

### Slice 5: doctor and CI

Add doctor checks only if the harness exposes a real integrity gap.

After local pass, add CI job after v0.3.2 tag governance and before v0.3.3 retrieval eval:

```text
C2c - v0.3.2.1 tag harness gate
```

Job `needs`: `[test, tag-governance-v032]` so C2c never runs before the v0.3.2 tag governance gate.

Then update:

- `docs/testing.md`
- `docs/project-status.md`

## Done Means

- Fixture schema is explicit and validated.
- Fixture corpus is sanitized.
- Harness runs in isolated eval vaults.
- Existing tag services are used.
- Hard-gate expectations match case by case.
- Summary JSON and failure records are stable.
- Hard-gate metrics are zero.
- Trusted tag filter checks pass.
- Feedback regression case shape is supported.
- v0.3.2 and v0.3.2.1 gates pass locally.
- Full pytest and compileall pass before completion.
- CI job and docs are updated after local pass.
