# v0.3.5 Stage 1 Provider Reliability / Packaging Gate Execution Plan

Status: completed. This execution plan is retained as the Stage 1 closeout
reference for the completed v0.3.5 baseline.

Date: 2026-06-09

## Objective

Make provider-backed indbase workflows provable from installed packages and
visible failure surfaces while preserving the v0.3.4 trust boundary:

```text
provider output = evidence or candidate
indbase decision = trusted state
```

Stage 1 does not add automatic retry, fallback execution, dynamic provider
loading, or user-facing provider selection.

## Decisions Locked For Stage 1

- PR CI blocks on fake provider gate, installed wheel import smoke, transition
  distribution smoke, and trusted-context consoler SDK contract smoke.
- Formal release additionally blocks on required real provider smoke with
  `INDBASE_PROVIDER_SMOKE_REQUIRED=1`.
- `indbase_integrations` remains the provider adapter package and must be
  included in wheels.
- `consoler-agent` extra is pinned to `consoler-agent-sdk==0.1.0`; ordinary
  dev sync and general pytest do not require the internal package index.
- `INDBASE_CONSOLER_CONTRACT_REQUIRED=1` upgrades missing consoler SDK or
  contract failure from explicit skip to hard failure.
- `provider_runs.failure_class` is a nullable persistent column. New failed or
  partial provider runs must write it; upgraded historical missing classes
  become doctor warnings.
- `provider_partial_success` is a non-fatal failure class for
  `provider_status = partial`.
- Required evidence roles are defined by capability policy.
- `provider_artifact_copy_failed` is an indbase evidence adoption failure, not
  proof that provider backend execution failed.
- Provider health has cheap and smoke levels. Ordinary doctor runs cheap
  checks; smoke gates run sample-level checks.
- Provider health findings are structured objects, not unparsed string lists.
- Ordinary doctor provider health omits `checked_at` for stable output.

## Canonical Failure Classes

| Failure class | Meaning | Typical surface |
| --- | --- | --- |
| `provider_unavailable` | Required provider package, runtime, binary, binding, or config prevents invocation. | task/error/doctor |
| `provider_timeout` | Provider invocation exceeded bounded timeout. | task/error/review when policy requires |
| `provider_contract_violation` | Reachable provider or response violates required contract, version, schema, capability, or evidence shape. | task/error/doctor |
| `provider_low_quality_candidate` | Readable candidate fails indbase adoption or promotion quality policy. | review/error |
| `provider_artifact_copy_failed` | indbase failed to copy or adopt returned provider artifacts into vault-owned evidence. | task/error/doctor |
| `provider_partial_success` | Provider returned partial result; non-fatal unless capability policy escalates. | output status/review by policy |
| `provider_unsupported_input` | Input is outside provider capability or profile support. | command output/error/review by policy |
| `provider_unknown_failure` | Failed provider run could not be mapped to a known class. | task/error/doctor warning target |

## Provider Health Shape

Stage 1 updates `docs/contracts/provider-capability-contract.md` with the
durable shape. The implementation should keep this shape stable enough for CI,
doctor JSON, and agent-readable summaries:

```text
provider_id
configured
binding_profile
provider_version
capabilities_ok
runtime_ok
smoke_status = not_run | skipped | passed | failed
findings[] = { severity, code, message, failure_class?, required?, skipped? }
```

No `checked_at` field belongs in ordinary doctor provider health output.

- `scripts/provider_installed_wheel_smoke.py`
- `scripts/provider_consoler_contract_smoke.py`

- Add `src/indbase_integrations` to wheel packages.

  run checks from outside the source tree.

  `--extra consoler-agent` in trusted package-index contexts.

```powershell

```

CI notes:

  `INDBASE_CONSOLER_CONTRACT_REQUIRED=1`.
- Fork-style contexts without package-index credentials may skip the consoler
  subgate, but the skip must be explicit.

## Slice 3: Evidence Completeness / Provider Artifact Boundary

Implementation files expected:

- `src/indbase_core/artifacts/evidence.py`
- `src/indbase_core/artifacts/evidence_store.py`
- `src/indbase_core/provider_runs.py`
- `src/indbase_core/doctor.py`
- `src/indbase_agent/artifact_view.py`
- provider mappers under `src/indbase_integrations/`
- provider/evidence/artifact-view tests under `tests/`

Implementation tasks:

- Define required evidence roles by capability policy for ingest, normalize,
  export, and pre-invocation failures.
- Ensure every provider run leaves an indbase-owned evidence index or bounded
  failure manifest.
- Detect missing evidence root, invalid evidence index, missing required roles,
  non-vault-relative copied refs, and copy failures.
- Classify copy/adoption failure as `provider_artifact_copy_failed`.
- Stop trusted promotion/output completion when required evidence adoption
  fails.
- Harden provider evidence artifact views against provider cache paths,
  provider URIs, raw trace bodies, private cache paths, and temporary
  directory leaks.
- Do not globally remove existing `vault_path` metadata from unrelated
  consoler artifact views in this stage.

Tests and gates:

```powershell

uv run python scripts/provider_fake_release_gate.py
```

## Do Not Touch

- Do not implement dynamic provider loading or a plugin marketplace.
- Do not add user-facing `--provider` options.
- Do not add default HTTP, queue, or MCP provider profiles.
- Do not add retry scheduler or fallback execution.
- Do not let provider output become trusted source state without indbase
  promotion/adoption policy.
- Do not modify external consoler protocol/runtime/store/schema files from this
  repository.

## Done Means For Stage 1

- Wheel-installed indbase proves provider integration imports and package data.
- Trusted CI proves installed-wheel consoler SDK contract with
  `consoler-agent-sdk==0.1.0`.
- New failed and partial provider runs persist `failure_class`.
- Doctor reports provider health, binding drift, evidence incompleteness, and
  historical unclassified provider runs with stable structured findings.
- Provider evidence views do not leak provider cache paths, provider URIs, raw
  traces, private cache paths, or temporary directories.
- `provider_stage1_release_gate.py` passes in a properly provisioned trusted
  environment.
