## Decision Summary

v0.3.1 makes the document category system trustworthy before tag governance, retrieval intelligence, or `ask`.

The phase owns **Big Category** foundations only:

```text
closed catalog -> category profiles -> post-ingest classification -> auditable run/results -> category search filters
```

It does not implement tag governance, tag candidate control, tag aliases, tag merge/deprecate, retrieval packages, or generated answers.

Primary correctness rule:

```text
Confident Assignment must be correct.
Abstain / Needs Review is an accepted outcome.
Wrong confident automatic category is a release blocker.
```

## Confirmed Decisions

- Big Categories are a closed, user-curated catalog.
- Automatic classification cannot create categories.
- Each document has exactly one Big Category or `uncategorized`.
- The default category catalog is replaced by one stable `indbase_default_v1` identity set.
- Old `minimal`, `academic`, and `full` templates are retired from new vault initialization.
- Existing vaults with legacy categories are not rewritten automatically; migration must be explicit and auditable.
- Chinese support is localization for the same stable category identities, not a separate category set.
- Users may add, edit, archive, or deactivate categories, but automatic classification may use only `classification_ready` categories.
- Category Profiles must contain positive and negative boundaries.
- Manual assignments and accepted suggestions outrank automatic classification.
- Post-ingest taxonomy runs after trusted revision/chunk/search creation and must not roll back ingest.
- Taxonomy execution errors are issues; intentional abstain is not an ingest failure.
- Category classification uses current-revision evidence and deterministic validation.
- Confident assignment requires both high confidence and sufficient margin over the second candidate.
- Classification records are auditable runs and per-document results, not just `documents.category_id` mutation.
- User corrections become explicit feedback and fixture/profile suggestions, not hidden online learning.
- Category search/filter belongs to this phase; tag search governance does not.
- Existing `classification_suggestions` / `classification_feedback` are legacy compatibility records, not the new core.

### `category_profiles`

Stores the language-neutral classification boundary.

```sql
CREATE TABLE category_profiles (
  category_profile_id TEXT PRIMARY KEY,
  category_id TEXT NOT NULL,
  profile_version TEXT NOT NULL,
  description TEXT NOT NULL,
  positive_cues_json TEXT NOT NULL,
  negative_cues_json TEXT NOT NULL,
  example_titles_json TEXT NOT NULL,
  example_quotes_json TEXT NOT NULL,
  aliases_json TEXT NOT NULL,
  classification_ready INTEGER NOT NULL,
  created_at TEXT NOT NULL,
  updated_at TEXT,
  FOREIGN KEY(category_id) REFERENCES categories(category_id)
);
```

Rules:

- At most one active profile per category/version pair.
- A profile is classification-ready only when required boundary fields are non-empty.
- Profile updates create a new profile version or update version metadata in a way that can stale old automatic assignments.

## Classifier Behavior

Inputs:

- current active document
- current revision chunks
- title and headings
- active classification-ready category profiles
- accepted manual metadata as context only
- optional existing accepted tags as weak context only

Forbidden confident evidence:

- old revisions
- archived documents
- rejected suggestions
- generated summaries
- model-only topic inference
- source path or filename as sole strong evidence

Default thresholds:

```text
confident_threshold = 0.85
margin_threshold = 0.15
```

Decision flow:

```text
if document has Manual Assignment:
  preserve category; optionally record review suggestion when classifier strongly disagrees
elif document has Accepted Suggestion:
  preserve category; optionally record review suggestion when stale
elif top category is classification_ready and confidence >= threshold and margin >= margin_threshold:
  write documents.category_id
  set classification_status = auto_classified
  write result outcome = confident_assigned
else if meaningful candidate exists:
  keep current category or uncategorized
  set classification_status = needs_review
  write result outcome = suggested
  write category_suggestion + review_item
else:
  keep category = uncategorized unless already manually set
  set classification_status = abstained
  write result outcome = abstained
```

Profile changes:

- Manual assignments are not stale.
- Accepted suggestions are not overwritten automatically.
- Prior automatic assignments with old profile versions become stale/recheck candidates.
- Stale state must be visible through doctor or classification list.

## Post-Ingest Integration

Run category classification after:

```text
source conversion/promotion -> current revision -> chunks -> FTS metadata
```

Rules:

- Do not run on source shells without trusted current revision/chunks.
- Do not roll back ingest if taxonomy abstains.
- Taxonomy execution errors create visible errors/review items.
- If source/revision/search succeeds but taxonomy execution fails, ingest may be `completed_with_issues`.
- If taxonomy abstains or creates review suggestion, ingest may still be `succeeded`.
- Re-ingest preserves manual and accepted categories.


Search:

```text
indb search <query> --category <category_id-or-name>
indb search "category:<category_id-or-name> <query>"
```

The implementation may choose one public syntax first, but category filtering must be deterministic and distinct from full-text matches on category names.

## Test Plan

Focused tests:

- migration creates category profile/localization/run/result/suggestion/feedback tables
- new vault uses only `indbase_default_v1`
- old template names are rejected for new vault initialization
- English and Chinese labels share stable category IDs
- category profile readiness requires positive and negative boundaries
- manual-only categories can be assigned manually but not auto-classified
- inactive-for-classification categories preserve old docs but are not used for new auto-classification
- used categories cannot be archived without migration
- post-ingest classification runs after trusted revision/chunks
- taxonomy abstain does not make ingest fail
- taxonomy execution error is visible and can produce completed_with_issues
- confident auto assignment writes `documents.category_id` and result evidence
- low confidence produces abstain
- low margin produces needs_review/suggestion
- manual assignment is preserved on re-ingest
- accepted suggestion is preserved on re-ingest
- profile update stales old automatic assignment without rewriting category
- user correction writes category feedback
- fixture suite imports/runs deterministically
- category search/filter returns only assigned docs
- category FTS metadata refreshes on category changes
- doctor catches broken profile/result/suggestion/FTS metadata

Regression tests:

- existing ingest/search/archive tests
- existing catalog/tag/manual metadata tests
- existing classification compatibility tests, updated only where legacy behavior is intentionally replaced
- v0.2 deterministic and doctor negative gates
