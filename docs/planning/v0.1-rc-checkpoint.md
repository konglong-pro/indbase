## Fixes From This Pass

The hardening gates exposed and covered one consistency risk:

- category/tag changes update DB metadata but previously did not refresh `chunks_fts` category/tag columns

The implementation now refreshes current document FTS metadata when:

- a document category is changed
- a category name is updated
- a document tag is added or removed
- a tag is renamed, archived, or restored
- an archived document is restored after an index rebuild removed its FTS rows

## Boundary

This checkpoint validates v0.1 Foundation RC hardening only. It does not include:

- PDF ingest
- OCR
- embeddings or hybrid search
- `indb ask`
- translation
- candidate cards
- background queue backend
- cloud sync
- physical delete
