# v0.2 Entry Plan

Status: active; MVP release close-out complete for deterministic local scope

Date: 2026-05-13

Precondition: [v0.1 Release Candidate hardening gate](v0.1-rc-checkpoint.md) is passing.

Canonical baseline: [mvp-v0.1-spec.md](mvp-v0.1-spec.md)

## Decision

v0.2 can start because the v0.1 Foundation RC gate is passing with no critical doctor findings, unexpected errors, index integrity errors, zero-chunk current revisions, or unsupported documents created.

v0.2 starts as Dogfood MVP hardening and expansion. It must not collapse into v0.3 intelligence work. The first implementation block is intentionally boring: add the v0.2 data substrate and keep current v0.1 behavior stable before enabling PDF/OCR behavior.

## Scope

v0.2 includes:

- PDF ingest v1
- OCR v0 and local OCR adapter
- OCR page records and quality flags
- embedding adapter and vector index
- hybrid search
- vector index rebuild
- category/tag suggestions
- classification feedback
- selected-chunk and full-document translation records
- stronger review queue where needed
- stronger harness boundaries for future model-backed work

v0.2 still excludes:

- `indb ask`
- claim-level answer workflow
- knowledge graph
- cloud sync
- multi-user support
- physical delete

## Implementation Blocks

Acceptance:

- fresh init applies v0.2 migration
- existing migration rules still hold
- v0.1 RC gate remains passing
- no PDF behavior changes yet

### M6.1 PDF Text Ingest v1

Status: complete. See [m6-pdf-ingest-checkpoint.md](m6-pdf-ingest-checkpoint.md).

Goal: move PDF from unsupported to supported best-effort text ingest without OCR.

Rules:

- PDF original is preserved
- successful text extraction writes Markdown, revision, chunks, and FTS
- failed extraction creates visible error/review state
- no searchable zero-chunk PDF document
- no OCR fallback yet
- no image-only PDF false success

### M6.2 OCR v0

Status: complete. See [m6-ocr-checkpoint.md](m6-ocr-checkpoint.md).

Goal: add local OCR for scanned PDFs/images behind explicit capability checks.

Rules:

- OCR writes `ocr_pages`
- OCR quality/confidence is visible
- low-confidence OCR creates review items
- OCR failure must not mark ingest successful
- OCR is explicit through `indb ocr run <doc_id>` and is not automatic PDF ingest fallback
- the current adapter reads local sidecar OCR files next to archived originals

### M6.3 PDF/OCR Hardening Gate

Status: complete. See [m6-pdf-ocr-hardening-checkpoint.md](m6-pdf-ocr-hardening-checkpoint.md).

Goal: harden PDF failure shells, OCR revision policy, OCR sidecar validation, and M6-specific doctor checks before vector work starts.

Rules:

- failed PDF text extraction may create a non-searchable source shell
- source shells must have no current revision, no chunks, and no FTS rows
- source shells must keep original files openable for later explicit OCR
- OCR defaults to refusing documents that already have a current revision
- `--force` is required for OCR to create a new current revision over an existing text revision
- OCR failure must not mutate an existing current revision or break existing search
- doctor must detect orphan OCR metadata and invalid source shell states

### M7 Embedding + Hybrid Search

Status: complete. See [m7-completion-checkpoint.md](m7-completion-checkpoint.md).

Readiness: complete. See [m7-readiness-checklist.md](m7-readiness-checklist.md).

Goal: add vector indexing without making ingest depend on embeddings.

Rules:

- embedding tasks are asynchronous or explicitly invoked
- FTS remains the reliable baseline
- vector index rebuild does not mutate document revisions
- hybrid search still returns chunk-bound citations
- embeddings index active current chunks only
- embeddings do not block ingest, OCR, or FTS search
- OCR current revisions and text-PDF current revisions are treated uniformly
- embedding staleness is bound to `chunks.content_hash`

### M7.1 Embedding Index Checkpoint

Status: complete. See [m7-embedding-index-checkpoint.md](m7-embedding-index-checkpoint.md).

Goal: implement embedding adapter, embedding status transitions, deterministic test vector storage, and `index rebuild --vectors`.

Rules:

- embed active current chunks only
- skip source shells, archived documents, and old revisions
- record embedding failures without breaking FTS
- doctor/gate must detect orphan embeddings

### M7.2 Hybrid Search Checkpoint

Status: complete. See [m7-hybrid-search-checkpoint.md](m7-hybrid-search-checkpoint.md).

Goal: merge vector and FTS retrieval while preserving source-snippet search semantics.

Rules:

- hybrid search still returns `doc_id`, `revision_id`, `chunk_id`, and snippet
- hybrid search must not generate answers
- archived/source shell/old revision results must not appear by default
- forced OCR current revision must be respected

### M8 Classification Suggestions

Status: complete. See [m8-classification-checkpoint.md](m8-classification-checkpoint.md) and [m8-classification-hardening-checkpoint.md](m8-classification-hardening-checkpoint.md).

Goal: suggest category/tags without silently overwriting manual metadata.

Rules:

- suggestions require confidence gates
- manual category/tag choices are preserved
- feedback is recorded separately
- suggestions are bound to current revisions
- old-revision suggestions are marked stale
- archived document suggestions are hidden and cannot be accepted by default
- rejected or accepted suggestions cannot be reused

### M9 Translation

Status: active; M9.3 translation hardening complete. See [m9-selected-chunk-translation-checkpoint.md](m9-selected-chunk-translation-checkpoint.md), [m9-full-document-translation-checkpoint.md](m9-full-document-translation-checkpoint.md), and [m9-translation-hardening-checkpoint.md](m9-translation-hardening-checkpoint.md).

Goal: write cited translation outputs without mutating source Markdown.

Rules:

- translations bind to source revision and chunks
- outputs live under `outputs/translations/`
- no source revision is rewritten
- selected-chunk translation is implemented
- full-document translation is implemented
- translation state-machine hardening is implemented
- translation does not create answers or candidate cards

### M10 Candidate Cards

Status: complete. See [m10-readiness-checkpoint.md](m10-readiness-checkpoint.md), [m10-candidate-extraction-checkpoint.md](m10-candidate-extraction-checkpoint.md), [m10-card-review-checkpoint.md](m10-card-review-checkpoint.md), [m10-card-hardening-checkpoint.md](m10-card-hardening-checkpoint.md), and [m10-completion-checkpoint.md](m10-completion-checkpoint.md).

Goal: extract source-bound candidate cards, review them explicitly, write accepted atomic notes, and diagnose generated-artifact drift.

Rules:

- M10.1 creates candidate records only
- every claim must bind to existing source chunks
- candidate records bind to source document and source revision
- source shells, archived documents, old revisions, and no-chunk current revisions are rejected
- M10.1 must not write `notes/atomic/`
- M10.1 must not implement accept/reject review actions
- M10.2 adds accept/reject review actions
- M10.2 accept writes cited atomic notes under `notes/atomic/`
- M10.2 reject writes no atomic notes
- accepted/rejected card terminal states cannot be reused
- M10.3 doctor checks candidate card records, source bindings, accepted notes, uncited claims, and orphan atomic notes
- M10 aggregate gate proves the whole candidate-card workflow is complete
