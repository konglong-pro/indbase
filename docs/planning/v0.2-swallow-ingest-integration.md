## Decision Summary

`swallow` becomes the complete conversion engine for indbase ingest. `indbase` keeps ownership of the trust boundary, vault identity, metadata, immutable revisions, chunks, indexes, task visibility, errors, review state, archive/restore behavior, and doctor checks.

This is not a v0.1 conversion tweak. It is a v0.2 ingest expansion that lets indbase use swallow's PDF, OCR, ASR, URL, Playwright, authenticated browser-capture, archive, and file conversion capabilities without weakening the durable data chain.

Core invariants:

```text
Swallow owns conversion.
indbase owns trust.
A candidate is not a revision.
Default search only indexes promoted current revisions.
Original or snapshot evidence must be local and durable.
No swallow success can bypass task, error, or review visibility.
```

## Goals

- Route all source conversion through a swallow-backed adapter.
- Preserve indbase as the system of record for originals, source snapshots, documents, revisions, chunks, FTS/vector indexes, review items, tasks, and errors.
- Support swallow's full conversion surface through explicit source-type commands and feature flags.
- Allow OCR and ASR outputs to become searchable automatically when they pass indbase promotion gates.
- Support URL, Playwright, authenticated browser, and archive captures as local durable snapshots.
- Support one input producing many indbase documents.
- Keep old indbase format-specific conversion retired from the production ingest path.

## Non-goals

- Do not replace indbase ingest orchestration with swallow's batch runner.
- Do not use swallow's HTTP service as the indbase ingest path.
- Do not let swallow write canonical indbase source revisions directly.
- Do not let swallow raw stores replace `.indbase/originals`.
- Do not index review candidates in default search.
- Do not enable external SaaS conversion providers by default.
- Do not implement `indb ask` or generated answers as part of this integration.
- Do not reintroduce direct-normalizer or MarkItDown fallback conversion in production ingest.

## Current Implementation State

Implemented:

- Optional pinned swallow dependency extras: `swallow` and `swallow-playwright`.
- Source-type CLI commands for file, folder, media, URL, browser-capture, and archive ingest.
- Local swallow SDK/Core adapter boundary, with no HTTP dependency.
- Shared promotion policy in `indbase_core.promotion_policy`.
- Durable artifact policy for source snapshots and chunk locators.
- OCR and ASR source locators written to chunks when candidates are promoted.
- URL/Playwright local snapshot ingest.
- Archive one-to-many logical document ingest.
- Doctor checks for swallow availability, artifact integrity, locators, candidate state, archive parent-child integrity, and promoted index state.
- Legacy indbase direct/MarkItDown conversion disabled in production ingest; disabled swallow conversion fails visibly as `legacy_conversion_retired`.

Remaining cleanup:

- `normalizers.py` remains only as a temporary test fixture baseline.
- Legacy MarkItDown fixture tests should be rewritten to construct swallow candidates directly before deleting `normalizers.py`.

## Ownership Boundary

| Area | Owner | Rule |
| --- | --- | --- |
| Source scan and duplicate detection | indbase | indbase decides ingest item identity and existing document binding. |
| Original file archive | indbase | `.indbase/originals` is authoritative. Swallow raw storage is cache/provenance only. |
| URL/browser source snapshot | indbase | The local captured payload becomes the durable source evidence. |
| Conversion execution | swallow | File parsing, OCR, ASR, web capture, archive extraction, worker routing, and raw conversion quality come from swallow. |
| Candidate mapping | indbase | Swallow output maps into an indbase `ConversionCandidate`. |
| Promotion decision | indbase | Swallow success never implies current revision promotion by itself. |
| Revision writing | indbase | indbase writes frontmatter, `doc_id`, `revision_id`, `canonical_path`, and immutable Markdown. |
| Chunking and indexing | indbase | Only promoted current revisions are chunked and indexed by default. |
| Task, error, review state | indbase | Every failed, partial, low-quality, or review-needed conversion is visible in indbase tables. |
| Doctor | indbase | Doctor verifies indbase records, required artifacts, swallow availability, and trust invariants. |

## Source Type Commands

The CLI should expose swallow's capability through source-specific commands instead of making one path command guess every source kind.

Preferred command shape:

```text
indb ingest file <path>
indb ingest folder <path> --recursive
indb ingest url <url>
indb ingest browser-capture <capture.json>
indb ingest archive <archive-path>
indb ingest media <audio-or-video-path>
```

Compatibility may keep `indb ingest <path>` as an alias for local file or folder ingest only. It must not implicitly trigger network capture, authenticated profile access, external providers, OCR model downloads, or ASR model downloads.

## Feature Flags And Provider Policy

indbase owns policy. swallow owns worker runtime parameters.

indbase config controls whether a source class is allowed:

```toml
[features]
swallow_ingest = true
web_ingest = false
login_profile_ingest = false
ocr = false
asr = false
external_ingest_providers = false

[ingest.swallow]
store_dir = ".indbase/cache/swallow"
config_path = ".indbase/config/swallow.config.yaml"
auto_current_quality_threshold = 0.75
review_quality_threshold = 0.45
min_markdown_chars = 80
archive_required_artifacts = true
```

`swallow.config.yaml` controls worker parameters such as OCR DPI, ASR model, ASR device, Playwright profile path, worker timeouts, screenshot behavior, and optional provider-specific settings.

Provider policy:

- Local file conversion is allowed only when `swallow_ingest=true`.
- OCR requires `ocr=true`.
- ASR requires `asr=true`.
- Local network capture, Crawl4AI, and Playwright URL capture require `web_ingest=true`.
- Authenticated browser-profile capture requires `login_profile_ingest=true`.
- Firecrawl or any external SaaS provider requires `external_ingest_providers=true` and explicit provider configuration.
- `web_ingest=true` alone must not enable external SaaS providers.

## Dependency And Runtime Boundary

Use an optional pinned Python dependency and in-process local adapter.

Recommended dependency shape:

```toml
[project.optional-dependencies]
swallow = [
  "swallow @ git+https://github.com/konglong-pro/swallow.git@<pinned-sha>"
]
```

Runtime rules:

- Use swallow's local SDK or core runner in process.
- Do not use swallow's HTTP service for indbase ingest.
- Do not vendor swallow into indbase.
- Record swallow package version, pinned commit when available, primary worker, worker versions, and worker chain in `converter_runs`.
- Missing optional dependency or worker runtime should produce doctor findings and visible conversion failures, not silent fallback success.

## Pipeline

The authoritative ingest pipeline stays in indbase:

```text
1. scan source input
2. create ingest_run and ingest_items
3. detect duplicate source hashes and existing normalized source URIs
4. archive local original or capture durable source snapshot
5. call swallow through the adapter for each eligible ingest item
6. map swallow output into ConversionCandidate
7. archive required provenance artifacts into indbase vault
8. run indbase promotion gate
9. if trusted-current: write revision, chunk, and index
10. if review-before-current: store candidate and review item, do not write revision
11. if failed: write error and review item, do not write revision
12. finalize ingest item, ingest run, and task
```

Folder ingest remains indbase-orchestrated. indbase may add internal concurrency later, but swallow batch must not become the authoritative ingest run.

## Promotion Gate

Promotion is the indbase decision that turns a candidate into a current source revision.

The policy is implemented in `indbase_core.promotion_policy`. All swallow-backed conversion paths, including archive one-to-many logical documents, must use this shared policy instead of maintaining local promotion rules.

Promotion classes:

- `trusted-current`: write revision, chunk, index, and make it current.
- `review-before-current`: store candidate and required artifacts, create review item, do not write revision.
- `failed`: write errors/review state, do not write revision.

Default automatic promotion conditions:

```text
swallow status is success
quality_score >= auto_current_quality_threshold
markdown_body is non-empty
markdown_body length >= min_markdown_chars
local original or local snapshot exists
required artifacts are archived
worker_chain and trace provenance exist
no fatal warning is present
source type is enabled by feature flag
external provider use is explicitly enabled when present
```

Status policy:

- `success` / `succeeded`: eligible for promotion after all other gates pass.
- `partial`: `review-before-current` by default.
- `partial` with `allow_partial_auto_current=true`: eligible for promotion after all other gates pass.
- `failed`, `error`, `cancelled`, timeout statuses, or unknown statuses: `failed`.

Hard bottom rules:

- Empty Markdown fails.
- Swallow failed status fails.
- Security or sandbox validation error fails.
- Missing archived original or required source snapshot cannot become trusted-current.
- Missing trace/provenance cannot become trusted-current.
- Missing worker-chain provenance cannot become trusted-current.
- Disabled source type fails before conversion.
- External SaaS provider use without opt-in fails before conversion.
- Partial status is review by default, not trusted-current.

Quality defaults:

```text
quality_score >= 0.75 -> eligible for trusted-current
0.45 <= quality_score < 0.75 -> review-before-current
quality_score < 0.45 -> failed
```

OCR and ASR are allowed to become trusted-current when they pass the same gate and have usable source locators.

Mode-specific policy:

- OCR requires `features.ocr=true`, source locators, and `allow_ocr_auto_current=true` for automatic promotion.
- ASR requires `features.asr=true`, timestamp-capable source locators, and `allow_asr_auto_current=true` for automatic promotion.
- URL, Playwright, Crawl4AI, and public web capture require `features.web_ingest=true`, durable web snapshot artifacts, web source locators, and `allow_web_auto_current=true` for automatic promotion.
- Authenticated browser profile or browser-extension capture requires `features.login_profile_ingest=true`; cookie/profile/session stores must not be archived.
- External provider capture requires `features.external_ingest_providers=true` in addition to any web flag.
- Archive one-to-many logical documents require archive-member locators that point back to durable package evidence.

Promotion reasons must be stored in `converter_runs.promotion_reason`. Reasons are user-visible review/error explanations; they must identify the first blocking gate instead of only saying that swallow failed.

## Candidate Review Flow

A review candidate is not a revision.

For `review-before-current`:

```text
converter_runs.status = pending_review
candidate_path = .indbase/cache/converters/<converter_run_id>.md
review_items.target_type = converter_run
documents.ingest_status = pending_review
document_revisions: no row yet
chunks: no rows yet
default search: no rows
```

Accepting a candidate:

```text
review resolve --accept
write document_revisions row
write immutable source Markdown
update documents.current_revision_id
chunk current revision
rebuild/update indexes
set converter_runs.promotion_status = promoted
```

Rejecting a candidate:

```text
review resolve --reject
set converter_runs.status = rejected
leave current revision unchanged
write no chunks or FTS rows
```

Default search must never include review candidates. A separate explicit command may search candidates, but results must be labeled as non-current and untrusted.

## Artifact Archive Policy

swallow cache is not durable evidence. indbase must copy required evidence artifacts into the vault.

Suggested location:

```text
.indbase/artifacts/
  doc_<id>/
    rev_0001/
      swallow_trace.jsonl
      swallow_manifest.json
      ingest_document.json
      rendered.html
      screenshot.png
      transcript.json
      ocr_result.json
```

Required evidence artifacts:

- swallow manifest
- swallow trace summary or full trace
- swallow ingest document JSON
- captured or rendered HTML for URL/Playwright
- screenshot for Playwright or login pages when generated
- OCR result JSON with page text, confidence, and boxes when available
- ASR transcript JSON with timestamps when available
- browser capture structured JSON
- archive extraction manifest or logical document map

Diagnostic artifacts may remain in swallow cache:

- intermediate page images
- normalized audio files
- extra debug screenshots
- temporary model outputs
- large worker dumps

If a diagnostic artifact is the only evidence for a chunk locator, it must be promoted to required evidence.

Real artifact policy:

- `trusted-current` requires all source evidence artifacts used by snapshots or locators to be copied into `.indbase/artifacts/...`.
- `documents.source_snapshot_path`, `source_files.source_snapshot_path`, and locator artifact fields must point to `.indbase/artifacts/...`, not `.indbase/cache/swallow/...`, absolute paths, temporary paths, or parent-directory escapes.
- locator `source_path` must point to the durable archived original under `.indbase/originals/...`.
- If required evidence cannot be copied into the vault, the candidate must be `review-before-current` or failed; it must not become searchable automatically.
- `converter_runs.candidate_path` may remain in `.indbase/cache/converter_runs/...` while pending review because it is not source evidence.

Doctor must report missing required artifacts as errors. Missing diagnostic artifacts are warnings at most.

## Source Locator Model

`chunks.source_page` is not enough for OCR, ASR, web capture, and archive extraction. Add a generic source locator.

Suggested schema field:

```text
chunks.source_locator_json
```

Locator examples:

```json
{"kind":"page","page":3}
{"kind":"page_region","page":5,"bbox":[10,20,300,120]}
{"kind":"time_range","start_seconds":42.5,"end_seconds":57.2}
{"kind":"web_snapshot","url":"https://example.com","artifact":"rendered.html","selector":null}
{"kind":"browser_capture","artifact":"capture.json","message_id":"msg_123"}
{"kind":"archive_member","artifact":"archive-map.json","member_path":"folder/source.md"}
```

Search snippets still bind to `doc_id`, `revision_id`, and `chunk_id`. The locator only explains how to find the chunk inside the archived source evidence.

## Source Type Rules

### Text And Office Files

Local `md`, `txt`, `html`, `csv`, `json`, `docx`, `xlsx`, and `pptx` use swallow conversion through the adapter. If they pass the promotion gate, they become trusted-current.

The old indbase normalizers are retired from the main ingest path. If `features.swallow_ingest=false`, indbase must fail conversion visibly with `legacy_conversion_retired` instead of falling back to direct normalizers or MarkItDown. `normalizers.py` may remain temporarily as a test fixture baseline, but production ingest must not call it.

### PDF And OCR

PDF revisions are textified source documents. The original PDF remains the authoritative archived original.

Rules:

- `documents.source_type = pdf`
- current revision is Markdown text extracted or OCRed from the PDF
- chunks should include page locators
- OCR chunks should include page-region locators when available
- `doc open --original` opens the PDF
- `doc open --revision` opens Markdown
- low-confidence OCR becomes review-before-current unless explicitly accepted

### ASR, Audio, And Video

ASR revisions are searchable transcripts. The original audio or video remains the authoritative archived original.

Rules:

- `documents.source_type = audio` or `video`
- current revision is transcript Markdown
- chunks should include time-range locators
- search should render timestamp ranges when available
- ASR without timestamps is review-before-current by default unless explicitly accepted

### URL, Playwright, And Authenticated Browser Capture

Remote content can become local-first only after a local durable snapshot exists.

Rules:

- `source_uri` may be the original URL
- `normalized_source_uri` is used for duplicate detection
- `source_snapshot_path` points to local captured evidence
- canonical revision is Markdown
- rendered HTML and screenshot are required evidence artifacts when available
- authenticated content must not archive browser profiles, cookies, or session storage
- privacy and access context must be explicit

Access contexts:

```text
public_url
dynamic_public_url
local_authenticated_profile
browser_extension_capture
external_provider_capture
```

Privacy flags:

```text
may_contain_cookies
contains_private_account_data
network_required_for_capture
requires_external_service
```

### Archive And One-to-many Extraction

Archive, export, browser, and conversation inputs may produce multiple logical documents.

Rules:

- the parent input is preserved as the original package
- each logical document gets its own `doc_id` and revision candidate
- child docs bind back to the parent package through source file and locator metadata
- search results reference child docs but `doc show` must trace back to the parent package
- do not force a large export into one giant Markdown revision

## Doctor Checks

Default doctor should stay lightweight:

- swallow package installed when `swallow_ingest=true`
- pinned version or commit recorded
- enabled worker imports are available
- feature flags and available workers do not contradict each other
- `.indbase/cache/swallow` is writable
- required artifacts exist
- converter runs do not reference missing candidates or artifacts
- source locators are valid JSON and valid for the source type
- review candidates are not present in default FTS
- promoted revisions have chunks and index rows
- missing originals, source snapshots, or canonical Markdown remain errors

`indb doctor --deep` may run heavier checks:

- OCR runtime smoke
- ffmpeg or ASR runtime smoke
- Playwright launch smoke
- Crawl4AI import or launch smoke
- Firecrawl connectivity only when external providers are enabled and credentials exist

Doctor diagnoses only. It must not silently fix ingest state.

Assertions:

- rejected candidates leave current revisions unchanged
- chunks contain source locators for OCR, ASR, URL, and archive inputs
- FTS and vector indexes only cover promoted current chunks by default
- errors and review items are queryable
- doctor detects missing artifacts and invalid source locator state

## Old Conversion Retirement Plan

Retire old indbase conversion in phases:

1. Add boundary objects: `ConversionCandidate`, `PromotionDecision`, `SourceLocator`, `ArtifactManifest`, and `SwallowProvenance`. Done.
2. Add schema migration for provenance, candidates, artifacts, promotion, locators, privacy, and one-to-many extraction. Done.
3. Add swallow adapter and route main conversion through it. Done.
4. Disable old normalizers as a production fallback. Done.
5. Convert behavior tests to assert indbase trust results, not old Markdown formatting. In progress.
6. Delete `normalizers.py` and remaining old MarkItDown fixture tests after all post-v0.2 tests use swallow fixtures directly.

Final target:

```text
indbase_core/conversion.py
  orchestration, state mapping, and promotion only

indbase_core/swallow_adapter.py
  all calls into swallow

indbase_core/normalizers.py
  deleted after remaining legacy test fixtures are rewritten
```

## Acceptance Checklist

- Swallow is optional and pinned.
- No HTTP service is required for ingest.
- indbase owns original archive and source snapshots.
- swallow output maps to candidates.
- candidate promotion is explicit and test-covered.
- review candidates are excluded from default search.
- OCR and ASR can be auto-searchable only after promotion gate success.
- URL and Playwright captures require local durable snapshots.
- required artifacts are copied into indbase vault.
- source locators exist for non-plain-text sources.
- external SaaS providers require explicit opt-in.
- one input can produce many documents without losing parent evidence.
- doctor covers swallow availability, artifact integrity, locators, candidates, and promoted index state.
- old indbase conversion is removed from the main path and later deleted after tests pass.
