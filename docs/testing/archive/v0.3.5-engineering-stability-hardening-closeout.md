# v0.3.5 Engineering Stability Hardening Closeout

## What Shipped

v0.3.5 closes the stability gaps left after the v0.3.4 provider baseline while
keeping the trust rule unchanged:

```text
provider output = evidence or candidate
indbase decision = trusted state
```

Shipped Stage 1 scope:

- installed-wheel smoke coverage for `indbase_core`, `indbase_cli`,
  `indbase_agent`, and `indbase_integrations`
- pinned `consoler-agent` extra for the installed contract path
- canonical provider failure classes and persistent
  `provider_runs.failure_class`
- evidence completeness checks and provider artifact boundary hardening
- provider health findings in doctor output
- Stage 1 aggregate release gate and CI jobs for wheel/distribution smoke

Shipped Stage 2 scope:

- normalize `--replace-current` regression and failure atomicity coverage
- source FTS lineage companion tables and index build records
- doctor drift detection for current chunks, FTS rows, and lineage coverage
- artifact view leakage redaction for agent-visible provider/output blocks
- deterministic retrieval regression fixtures and the v0.3.5 hardening gate

## Frozen Behavior

- Normalize replace writes a new immutable source revision or leaves the
  previous current revision and search state intact on failure.
- Default source search indexes trusted current source revisions only.
- Provider evidence and output artifacts remain derived records and do not
  enter default source search.
- Agent-visible artifact views return bounded summaries and `indbase://...`
  references rather than provider cache paths, absolute vault paths,
  `file://`, or provider URIs.
