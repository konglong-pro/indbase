# v0.3.4 Provider Evidence / Trust Correlation Closeout

## What Shipped

v0.3.4 makes indbase a capability consumer, trust boundary, evidence compiler,
and vault state owner.

Shipped scope:

- provider capability contracts and fake provider fixtures
- swallow ingest behind `SwallowIngestProvider`
- transition output behind `TransitionOutputProvider`
- provider result to indbase evidence-package mapping
- copied provider evidence under `.indbase/artifacts/provider_runs/<id>/`
- `provider_runs` records and adopted provider-run links
- provider error mapping into tasks, errors, review items, output warnings, and
  doctor state
- provider-aware doctor summary and copied-evidence health checks
- provider evidence summary views under `indbase://provider_runs/<id>`
- agent operation trace provider correlation without direct provider backend
  calls
- search pollution coverage for rejected/partial candidates, evidence files,
  exports, normalize without replace, and old revisions

## Frozen Behavior

Provider output is evidence or a candidate. indbase alone decides trusted
source state, output state, review state, errors, and search indexing.

Provider cache is disposable. Copied indbase artifact evidence is durable.

Default source search indexes trusted current source chunks only. Export
artifacts, copied provider evidence text, unpromoted candidates, and old
revisions are not default-searchable.

`indbase_agent` does not call provider backends directly and does not expose
provider cache paths, `swallow://...`, or `transition://...` artifact URIs.

## Historical PDF Gate Decision

`m6_pdf_ingest_gate.py` and `m63_pdf_ocr_hardening_gate.py` predate the provider
model and encoded legacy MarkItDown/direct-PDF success assumptions. Under
v0.3.4 those assumptions are intentionally retired.

The gates now serve as historical guard scripts for provider-era semantics:
legacy PDF direct conversion must fail visibly as `legacy_conversion_retired`,
must not create source revisions, and must not pollute source search. Real PDF
provider success remains an environment-gated provider smoke concern.

## Known Limitations

This machine did not validate successful real PaddleOCR, faster-whisper, or
MarkItDown heavy-runtime paths. Missing runtime probes were verified to fail
visibly through provider runs, errors, and review items without creating source
revisions or search pollution.

Heavy runtime success requires installing the relevant swallow extras and
runtime dependencies, then running the real provider smoke in an environment
that has the models and binaries available.
